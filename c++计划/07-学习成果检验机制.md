# 学习成果检验机制

> **核心信条**：学习成果 = 你能独立产出的最低水平，不是你看过的最高水平。
> 这份文档不是用来读的，是用来**每天 / 每周 / 每月真正去做**的。

---

## 0. 为什么必须检验

**面试官只看你能产出什么，不看你"看过什么"。**

| 看过/抄过 | 真正学会 |
|---|---|
| 看视频时疯狂点头 | 关掉视频能复述核心思想 |
| 抄题解 AC 了 | 一周后能盲写 70% |
| 看博客觉得"原来如此" | 能讲给完全不懂的人听 |
| 用术语挡："就是 RAII 嘛" | 能解释 RAII 解决了什么具体问题 |
| commit 了 = 学会了 | 改造代码、解释 bug、迁移场景 |

**只要中一条假学会信号，回头检验，不要前进。**

---

## 1. 假学会的 6 个危险信号 ⚠️

```
□ 看视频/博客时一直点头："原来如此！"
□ 抄题解的代码 AC 了就过，没自己重写一遍
□ 跟 ChatGPT 问完概念，复述时只能引用它的话
□ 能看懂别人的代码，但合上 IDE 写不出来
□ commit 了 = 学会了
□ 用术语挡知识，但讲不出术语背后的"问题 + 方案"
```

---

## 2. 检验金字塔（从弱到强）

```
        ╱╲   Level 5  教别人 / 写博客 / 模拟面试 ← 最强
       ╱  ╲  Level 4  跨场景迁移：同一知识点用在新问题
      ╱────╲ Level 3  盲写代码：关 IDE、空白页、计时
     ╱      ╲Level 2  费曼讲解：对着摄像头大白话讲一遍
    ╱────────Level 1  自问自答：能回答标准八股题
   ╱──────── Level 0  "我看懂了"   ← 最弱，几乎等于没学
```

**铁律**：每个知识点至少做到 **Level 2**，否则不算"学会"，不能勾掉计划里的 □。

---

## 3. 五种核心检验法

### ① 盲写代码（Blank Page Test）⭐⭐⭐⭐⭐

**最硬的检验**，没有之一。

**操作步骤**
1. 关闭所有资料、IDE 自动补全、AI
2. 打开记事本 / 拿张纸
3. 计时（一般 15-30min）
4. 写出关键代码 + 实机编译运行
5. 写不出 = 没学会，立刻回去重学

**触发时机**：每周末固定 1 次；每个新概念学完 24 小时内做一次。

---

### ② 费曼讲解（对着摄像头讲）⭐⭐⭐⭐⭐

> "如果你不能用简单的话讲清楚一个概念，说明你没真正理解。" — 费曼

**操作步骤**
1. 打开手机录像 / 录音
2. 假装在教你妈妈 / 完全不懂代码的朋友
3. 不允许用术语挡（如果用，必须立即解释这个术语）
4. 卡壳处 = 没学会的地方
5. 回听 — 你会震惊地发现自己讲得有多差

**触发时机**：每天 5 分钟讲一个当天学的概念；每周末讲一个本周最难的。

---

### ③ 八股闭卷自测（30min 模拟面试）⭐⭐⭐⭐

**操作步骤**
1. 每周末固定 30min
2. 抽 5-7 道八股题（自己 / ChatGPT / 知乎收集）
3. 闭卷写答案（关网、关 AI）
4. 写完对照标准答案 / 让 AI 批改
5. 错的、模糊的、答不全的，记入"复习清单"

**触发时机**：每周二（周末复盘）；每月底集中 1 轮 30 题。

---

### ④ 故意制造 bug + 解释 ⭐⭐⭐⭐

**真正懂一个东西，是知道"它不那么做会怎样"。**

**操作步骤**
1. 把你的代码故意改坏
2. 自己解释会发生什么、为什么
3. 实机跑一遍验证你的解释

**示例**
- fork 后子进程不 exec 也不 exit，会发生什么？
- 多进程 echo 父进程不 close(conn_fd) 会怎样？
- ThreadSafeQueue 把 cv.wait 改成 if 而不是 while 会怎样？
- MyString 拷贝构造写错成浅拷贝，运行会出什么 bug？

**触发时机**：每个新模块学完做 3-5 个 bug 实验。

---

### ⑤ 跨场景迁移（最高级）⭐⭐⭐⭐⭐

**用学过的知识解决一个没学过的问题。**

**示例**
- 学了 mutex + cv → 写一个限流器，限制每秒最多 5 个请求通过
- 学了 fork → 写一个任务并行器，传入 N 个函数 fork 出 N 个进程并行跑
- 学了 unique_ptr → 写一个 unique_fd，自动 close 文件描述符
- 学了 SIGCHLD → 多进程 echo 用 waitpid 同步回收，对比 SIG_IGN 异步的区别

**触发时机**：每周至少做 1 道迁移题；每月底做 3 道大迁移。

## 4. 三层检验节奏（这是你真正要执行的）

### 🌅 每日检验（睡前 5min）

用 `daily_check.md` 模板回答 4 个问题：
1. 今天写的代码，明天我能盲写出 70% 吗？
2. 今天学的概念，能用 3 句话讲给外行听吗？
3. 今天的代码每一行我都能解释为什么这么写吗？
4. 明天起床要做的第一件事是什么？

**写不出来的地方就是漏洞 — 漏洞才是金子。**

---

### 📅 每周检验（周二 90min，固定时段）

#### 周末"期末考"模板

```
[阶段 1] 盲写考 (40min)
  □ 题 1: 本周核心代码 1（10-15min）
  □ 题 2: 本周核心代码 2（10-15min）
  □ 题 3: 本周核心代码 3（10-15min）

[阶段 2] 八股闭卷 (30min)
  □ 5-7 道本周相关八股题
  □ 每题写完对照标准答案 / 让 AI 批改

[阶段 3] 口述 (15min)
  □ 录音 / 录像
  □ 3min 讲清本周最难概念 A
  □ 3min 讲清本周最难概念 B

[阶段 4] 评分 + 复盘 (5min)
  □ 总分 ≥ 80 → 当周通关
  □ 总分 60-80 → 主要漏洞写进下周计划开头
  □ 总分 < 60 → 下周主线砍掉 1/3，先补漏洞
```

#### 评分标准（每周一致，便于纵向对比）

| 维度 | 满分 | 标准 |
|---|---|---|
| 盲写正确率 | 40 | 编译能过 + 行为正确 |
| 八股得分 | 35 | 抓住关键点 + 表达清晰 |
| 口述清晰度 | 15 | 回听不脸红 = 满分 |
| 复盘深度 | 10 | 漏洞具体可执行 = 满分 |

**期末考结果记入 `progress.md`**，纵向看自己每周分数走势。

---

### 🗓️ 每月检验（月底 2h）— 模拟面试

#### 操作流程

```
[1h 模拟面试]
  - 找朋友 / 用 AI 当面试官 / Pramp 等平台
  - 全程录音
  - 题目范围：当月主线 + 累计算法 + 八股

[30min 回听]
  - 哪里卡壳？
  - 哪里讲混了？
  - 哪里被反问就答不上？

[30min 复盘]
  - 写进 progress.md 的"失败/教训记录"
  - 列出下月必须补的 5 个漏洞
```

#### 5 月底（5.31）月度面试题预设

> 提前准备好，到时候直接用，不要临时找题。

**C++ 基础（5 题）**
1. unique_ptr 为什么不能拷贝？怎么实现的？
2. shared_ptr 的引用计数线程安全吗？为什么放堆上？
3. std::move 实际做了什么？返回值是什么类型？
4. lambda 的 `[=]` 和 `[&]` 区别？什么时候会有悬空引用风险？
5. RAII 是什么？它解决了什么具体问题？举一个非内存的例子。

**Linux 进程/线程（5 题）**
6. fork 之后父子哪些资源共享、哪些独立？COW 是什么？
7. 僵尸进程怎么产生？3 种避免方式？
8. 多进程 vs 多线程 echo 优劣对比（≥4 个维度）
9. SIGCHLD 设为 SIG_IGN 和用 waitpid 异步回收的区别？
10. mutex + condition_variable 为什么 wait 要配合 while 而不是 if？

**网络（3 题）**
11. TCP 三握四挥（手画）
12. send / recv 为什么需要循环？返回值都有哪些情况？
13. SO_REUSEADDR 解决了什么问题？

**算法（2 题）**
14. 现场写一道链表中等题
15. 现场写一道双指针 / 滑动窗口题

## 6. 检验心态规则

1. **对自己狠一点**：60 分及格不是目标，**80 分才算过**
2. **不要美化数据**：周末期末考没过就是没过，写进 progress.md
3. **漏洞才是金子**：发现漏洞应该高兴，因为你刚刚避免了面试翻车
4. **检验时间不能省**：每周 90min 期末考是雷打不动的，**主线没做完也要做这 90min**
5. **不要"再学一遍再检验"**：你永远不会准备好，**先考再补**

## 8. 立即落地

**今晚开始的动作**：
1. 把今天学习的概念，用费曼法讲 3 分钟（录音）
2. 回听一遍，写下 2 个讲不清的点 → 进漏洞清单
3. 明天起床先消化这 2 个漏洞，再开始新内容

**周二（5.26）必做**：
- 用本文档第 4 节"周末期末考模板" 做一次 W02 期末考
- 分数记入 `progress.md`

**5.31 必做**：
- 用本文档第 4 节"月度模拟面试"做一次 5 月期末面试
